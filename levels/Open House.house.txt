# Open House -- the port's own house, and the worked example for building one.
#
# Built with `make levels`, which runs `glidertool house build` over this file and
# writes assets/levels/Open House.house. The binary is a build product; this text is
# the source, and it is the thing to edit.
#
# ---------------------------------------------------------------------------
# Why this house exists
# ---------------------------------------------------------------------------
#
# docs/PLAN.md Stage 2 asks for "new houses designed against the quantitative
# profile of the originals in docs/analysis/original-houses.md -- comparable room
# counts, object vocabulary and difficulty curve, not just 'some rooms'". Section
# 10.2 of that document turns the measurements of all 4,070 shipped rooms into a
# table of targets per size tier. This house is the tutorial tier, and every number
# in the "what it hits" list below is a line of that table. That is the whole design
# method: the shape came second, the numbers came first.
#
# It is also meant to be read. A player who likes the game and wants to build
# something will find no editor here yet -- porting the original's is docs/PLAN.md
# Stage 5 -- so the honest offer is this format and this file, which is why the
# comments explain the arithmetic rather than just naming the rooms.
#
# ---------------------------------------------------------------------------
# What it hits, against docs/analysis/original-houses.md 10.2, tutorial column
# ---------------------------------------------------------------------------
#
#   real rooms            43        target 35-45
#   occupied floors        7        target 6-7
#   occupied suites       10        target 9-10
#   grid density        0.614       target 0.6-0.65     (43 of 7 x 10 cells)
#   total objects        133        target 78-138
#   objects/room        3.09        target 2.2-3.1
#   empty rooms         20.9 %      target ~20 %        (9 of 43)
#   rooms at the 24 ceiling 0       target 0            (the fullest holds 5)
#   enemies/room       0.047        target 0.0-0.1      (one drip, one cobweb)
#   prizes/room        0.256        target 0.03-0.29    (11 of them)
#   stars                  1        target 1
#   batteries              1        target 0-1
#   rubber bands           1        target 0-1
#   dark rooms             0 %      target 0 %
#   distinct what codes   26        target 15-48
#   total points      11,700        target 8,500-12,500 (4,300 rooms + 7,400 prizes)
#   firstRoom          f1 s57       12 of 22 houses start on floor 1, 19 of 22 in
#                                   the suite 54-69 band (10.3 step 1)
#
# Thirteen of those rows are asserted, not claimed: TestOpenHouseMatchesTheTutorialProfile
# (internal/replay/openhouse_test.go) walks this file and reports which one left its
# band. The dark-rooms row and 10.2's BFS eccentricity are the two it cannot compute,
# both because the rule lives in internal/render or internal/game and internal/house
# cannot import either -- docs/IMPROVEMENTS.md 4.16. Dark rooms was checked by eye
# instead, with `glidertool render -all`, and all 43 are lit.
#
# Two targets are deliberately missed, and both for the same reason.
#
# 10.3 step 3's background mix wants 27 % user-structure and 17 % user-open art.
# This house has none, and may not: a house of ours is restricted to the built-in
# backgrounds 2000-2017 and the built-in object art -- no kUserBackground (>= 3000),
# no kCustomPict, no kTV, no custom `snd `. Not because gliderGo cannot read house
# art: it reads it as plain PNGs named by PICT id under houseart/<name>/pict/, and
# painting one would be easy. The obstruction is where the bytes may sit.
# assets/extracted/ is diff-locked against the extractor by `make assets-check`, so
# our art cannot go in beside 1994's; and the levels archive holds houses and nothing
# else, while -houseart *replaces* the one art root, so handing this house its own
# pictures takes that art away from every shipped house. Both halves are
# filed as docs/IMPROVEMENTS.md 4.15. So the mix here is 72 % indoor, 21 % air and
# 7 % kDirt where the corpus is 15/22/10 plus 44 % of its own art. Nothing about the
# *play* depends on it -- and note that three of 10.3's rules (step 4's kInvisLight
# for user-art rooms, and 10.5's kSoundTrigger and kTV traps) have nothing to apply
# to here, so they go live the day a house does carry art.
#
# 10.3 step 5 wants interiors filled to 11-13 objects. These hold 3-5. The tutorial
# tier's 2.2-3.1 objects/room and the 11-13 per interior cannot both be true unless
# most rooms are empty or outdoors, which is how Demo House does it: the corpus has
# 2,326 rooms with no blower at all, because most of its rooms are sky. Every
# interior here needs two floor vents and a light before it needs anything else (see
# the next section), so 3 is the floor and 5 is what is left. The house reads plainer
# than a 1994 interior and that is the honest consequence of the tier, not an
# oversight. The contradiction is the document's and is filed against it as
# docs/IMPROVEMENTS.md 4.18: steps 5, 10 and 12 all quote corpus *means* (7.7
# objects/room) at a tier whose ceiling is 3.1.
#
# ---------------------------------------------------------------------------
# Why every room has two vents: the arithmetic that fixes the layout
# ---------------------------------------------------------------------------
#
# Gravity is 3 and it *assigns* VDesiredVel every frame, so an unpowered glider sinks
# exactly 3 px per frame; NormalThrust is 5, so it cruises 5 px per frame. The glide
# ratio is therefore 5:3 -- 5 px along for every 3 px down -- and it is not
# negotiable.
#
# A room is 512 px wide and the usable band is CeilingLimit 8 to FloorLimit 312: 304
# px of sink, which buys 507 px of travel. A full traverse, wall to wall, is 489 to
# 512 px. So **no room is crossable in one glide** with any margin at all, and lift
# is not decoration -- it is the floor plan.
#
# kFloorVent's column is 4 px wide at h = H+22..H+26 (FloorColumnWide, offset by
# HalfWide(srcRect)-2), and LiftIt fires on plain overlap with no key condition, so
# the *glider* is caught while its left edge is in a 52 px window, h = H-25..H+25.
# With `distance 269` the hover cut-off is top = V-D-20 = 16, and the glider settles
# rocking between top 12 and top 17 (internal/replay/testdata/duct.script pins this).
#
# Two vents at h 120 and h 336 give windows of left 95..145 and left 311..361, and
# the three legs of an eastward crossing are:
#
#   enter at left -23, top 89   ->  118 px to window 95   sink 71   top 160  ok
#   leave window at left 145    ->  166 px to window 311  sink 100  top 112  ok
#   leave window at left 361    ->  128 px to exit 489    sink 77   top 89   ok
#
# and the westward crossing is its mirror. Every leg has 130 px or more of clearance
# above FloorLimit, which is what makes the house playable rather than merely
# possible. One vent does not work: a single vent at h 256 leaves the glider arriving
# at top 289 with FloorLimit at 312, a 3 px margin that the first mistake eats.
#
# **Read that table carefully: each leg starts at the ceiling, and a glider only gets
# there by stopping.** This was got wrong here first and the simulation corrected it.
# A glider that *flies through* a window is inside the 52 px catchment for about ten
# frames at cruise, and LiftIt only sets VDesiredVel to -6, so it gains **60 px** --
# against the 0.6 px of height it spends on every px it travels. Break-even is a vent
# every 100 px, and at 216 px apart these two are nowhere near it: holding the arrow
# down loses roughly 100 px per room and kills the glider in the third one. Riding the
# column -- release, rise to top 12..17, press, glide -- is the whole mechanic, and
# `AddActiveRect` gives the vent no key condition precisely so that letting go works.
#
# That is not a shortcoming of two vents per room. The corpus averages 1.49
# blower-class objects per room (10.2), so the originals are *more* dependent on
# stopping than this house is, and a house crossable with one key held down would have
# removed the thing the game is about. So the layout below is unchanged and it is the
# arithmetic above that was wrong; internal/replay/testdata/open-house.script is the
# route that follows from the corrected version.
#
# A vent needs `state 1`. AddActiveRect is passed `a.State != 0` (hotspots.go:94), so
# a vent switched off does not blow, and 24 of the corpus's 1,458 are exactly that.
#
# Rooms at the end of a row are entered from one side only and get **one** vent, on
# the side they are entered from -- 3 objects instead of 4, which is where a third of
# the object budget came from.
#
# ---------------------------------------------------------------------------
# The climb
# ---------------------------------------------------------------------------
#
# Six staircase pairs, each one kUpStairs at `28 336` below and one kDownStairs at
# `28 16` on the floor above in the same suite, which is what CheckForStaircasePairs
# wants (HouseLegal.c:961-1045) and what `glidertool house lint` checks. V is 28 in
# all 163 corpus placements and this house does not depart from it.
#
# The critical path zigzags, one room east between each flight:
#
#   4 Furnace Room (f1 s57)  -up->  10 Front Hall    (f2 s57)
#                            -east-> 11 Parlour      (f2 s58)  -up->
#   21 Nursery     (f3 s58)  -east-> 22 Sewing Room  (f3 s59)  -up->
#   30 Attic Stair (f4 s59)  -east-> 31 Cedar Closet (f4 s60)  -up->
#   36 Tower Landing (f5 s60) -east-> 37 Tower Stair (f5 s61)  -up->
#   41 Belfry      (f6 s61)  -- the star.
#
# The seventh flight is the basement branch: 5 The Laundry down to 0 Under the
# Foundations.
#
# MoveItUp fires on GliderInRect(112x32 at (H,28)) **and** !HeldRight; MoveItDown on
# !HeldLeft. So a glider crossing a room with the direction key held sails past the
# staircase, and taking it is a deliberate release -- which is the original's own
# design and is what lets a staircase live in a corridor. Leaving the h 300 window at
# left 325 and holding right, the glider is inside the trigger box (left 336..400, top
# 28..40) from left 336 to left 400; release at about 348 and it coasts to 354 and
# sinks through top 28..40 over five frames with the key up.
#
# That is why a room with a kUpStairs has its second vent at **h 300** and not h 336:
# the trigger box needs the glider to arrive in the top band inside left 336..400,
# and a window ending at 361 puts it there. The kUpStairs art is 160x267 at v 28..295
# and a floor vent is v 305..316, so the two never collide.
#
# Arrivals were checked in both directions. GetUpStairsRightEdge searches the
# *destination* for a kDownStairs and returns H+159 (env.go:122-166 -- the crossed
# pairing is the C verbatim), so ReadyGliderForTripUpStairs lands the glider at left
# 127, top 52: inside the h 120 window 95..145, so it is caught and lifted, and
# outside the kDownStairs box 16..80, so MoveItDown cannot immediately re-fire.
# Downward, GetDownStairsLeftEdge returns H+1 and the glider lands at left 337, top
# 148 -- 12 px right of the h 300 window, recovered by holding left for five frames
# with 54 frames of sink in hand.
#
# ---------------------------------------------------------------------------
# Walls, floors, light, and what kills
# ---------------------------------------------------------------------------
#
# `bounds` is 0 in every room here and that is not laziness: DetermineRoomOpenings
# reads it only when Background >= 3000 (room.go:139), so on a built-in background it
# is dead data that misleads tools -- 10.5's fourth bullet, and 27 shipped rooms get
# it wrong. The walls come from the tiles.
#
# The nine interiors and kSky share one rule: tiles[0] == 0 means a wall on the left,
# tiles[7] == 7 means a wall on the right. So the four idioms used here are
#
#   0 1 1 1 1 1 1 7   walled both       0 1 1 1 1 1 1 1   walled left, open right
#   1 1 1 1 1 1 1 1   open both         1 1 1 1 1 1 1 7   open left, walled right
#
# and kSky writes 2 for its open column instead of 1, which is what 264 of its corpus
# rooms do.
#
# kDirt is the same rule with one digit changed, and the digit disagrees with the flag
# beside it: the threshold tests `leftTile == 1` while leftOpen tests `leftTile != 0`
# (room.go:198-201, reproduced not reconciled). The escape functions read the
# *threshold* (escape.go:366), so for the glider a dirt room is walled by tile **1**
# and open by tile 0. The three cellar rooms use that, and room 1 is all zeros because
# GetNumberOfLights lights a dirt room only when all eight tiles are 0 -- which is one
# object saved.
#
# Every other room is lit by an object, because there are no dark rooms in the
# tutorial tier: kCeilingLight (v 4 in all 160 corpus placements), kLightBulb in the
# attic and the cellar, one kTableLamp, and two kWallWindows, which count as light
# without being lamps (locale.go:1376).
#
# The floor kills. So do eleven furniture types, nine appliances, and the enemies --
# and the crossing legs above put the glider at a known height at every h, so the
# three lethal pieces here (a table, a shelf of books, a trunk) sit below v 200 in the
# central gap h 160..300, where the crossing never reaches but a player who drops for
# a prize does.
#
# **No lethal rect may cross a lift column.** That is stronger than keeping it out of
# the 52 px catchment window and it is the rule that matters, because a glider inside
# a column is rising under power and cannot steer out of anything drawn there. The
# column is only 4 px wide -- h H+22..H+26, so 142..146 and 358..362 for vents at 120
# and 336 -- and a piece of furniture that spans it is a death at the vent the player
# was aiming for, with the vent visible underneath it as an invitation. The first draft
# of The Trunk Room had exactly that: the corpus-verbatim kTrunk rect 228 221 308 365
# covers h 358..362 from v 228 down, so an arrival 45 px below the designed line died
# on the lift.
#
# So every piece that stands on the floor here is inside h 180..324 -- the 168 px gap
# between the two vents' *art*, which spans h H..H+48, so 120..168 and 336..384. That is
# a tighter rule than the column one and it buys a second thing: a vent half hidden under
# a trunk or a rug reads as a decorated floor rather than as a lift, and the whole house
# depends on the player seeing where the lifts are. 144 px of furniture fits in 168 with
# 12 px to spare each side, which is why the trunk and the rug are both at 180..324.
#
# The same reasoning is why a prize is never inside a window either -- not because it
# would kill, but because the column lifts continuously from the floor up, so a prize
# in a column can be flown past and never landed on. Every prize here is in the gap
# between two windows, collected by gliding across, releasing, sinking straight down
# onto it, and gliding back to the nearer window: 66 px back from the h 210 prizes and
# 39 px from the h 400 ones, against a 200 px sink budget.
#
# Harmless art is allowed anywhere, and is used: the fourteen clutter types have no hot
# spot at all (hotspots.go:656-668), so the fireplace, the mirror, the bear and the rug
# are wall decoration the glider flies in front of. kChimes is the nice case -- it gets
# ChimeIt, which only rings -- and the Music Room's corpus-verbatim rect 44 214 118 242
# sits squarely on the eastward line at v 53..73, so crossing that room plays the
# chimes. That is a detail worth keeping rather than an overlap worth fixing.
#
# The nine empty rooms are kSky: lit by definition, floorless, so they drop the glider
# into the room below -- 10.3 step 2's free vertical branch. Each is walled on its
# outward side and open toward one occupied room, so it can be flown into and fallen
# out of, and each has a floored room somewhere beneath it. A sky room with nothing
# under it would be a trap: MoveRoomToRoom to a room that does not exist is a no-op
# but OffsetGlider still runs, so the glider wraps 322 px and falls again forever.
#
# One thing that cannot happen here, and it took checking: a glider leaving a room
# sideways keeps its height and velocity (the side arms of MoveRoomToRoom call
# OffsetGlider and only set EnteredRect, transit.go:388-434), so a glider entering a
# sky room while still rising would escape through its absent ceiling. It never is.
# The nearest lift window is 95 px from a room's edge and a glider leaving a column at
# VVel -6 is sinking again after 12 px, so by the wall it is always on the way down.
